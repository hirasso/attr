# For the AGENTS

`hirasso/attr` – a tiny PHP library (Composer package) that generates HTML attributes. Zero runtime dependencies. Supports PHP 8.2+ (see `composer.json`). Pest for tests, [Mago](https://mago.carthage.software/) for lint/format/analysis, Changesets for releases.

## Key commands

```bash
composer test           # Pest
composer test:watch     # Pest in watch mode
composer test:coverage  # HTML coverage report in tests/reports (Herd + Xdebug)
composer analyse        # Mago static analysis
composer lint           # Mago lint (with --fix)
composer format         # Mago format
pnpm changeset          # add a changeset for user-facing changes
```

A Husky pre-commit hook runs Mago analyze/lint/format on staged PHP files.

## Code style

- derive from the existing code
- keep comments as short as possible
- do not add comments if not really required
- only use languages I know. No python please
- Use `/** */` block comments (not `//`) for anything that's not an "end of the line" comment
- docblocks state _what_ a thing does, never _why_ it does it or why it was built that way (exception: Inline docs like e.g. "using the raw value because..."); no {@see} cross-references at all; skip the docblock entirely if the name is self-explanatory; hard ceiling of 3 lines, shorter preferred.

## Before making changes

- if the change is big, always first propose what you are planning, even if not in plan mode
- the public API (`attr()`, `jsonAttr()`, `Builder`, `Attr`) is used by others. Ask before introducing breaking changes

## After making changes

- Keep inline code comments as short as possible. Be extremely concise and sacrifice grammar for the sake of concision
- Update `README.md` if public behavior or API changes
- Add a changeset (`pnpm changeset`) for user-facing changes

### PHP

- Only use features available in the **minimum** PHP version declared in `composer.json` (currently 8.2) – CI tests 8.2 to 8.6
- `declare(strict_types=1);`, `final readonly` classes where possible, fully qualified global functions (`\is_array()`)
- Classes in `CamelCase`, methods / functions in `camelCase`
- Internal helpers live in `src/Internal/` (`Hirasso\Attr\Internal\`) and are not public API
- No runtime dependencies. Don't add any
- After making changes, run `composer analyse` and `composer test`
- Add new tests in `tests/Feature/` when it makes sense. Don't overdo it!
- Keep code DRY! Ask if unsure.
- Prefer fewer, bigger classes: bundle related functionality in one class/file instead of many small ones. A class doing several related, contained jobs is fine

## Project structure

| Path | Purpose |
|------|---------|
| `src/Attr.php` | Core: validates and transforms attribute arrays, `jsonAttr` |
| `src/Builder.php` | Fluent builder returned by `attr()` |
| `src/helpers.php` | Global `attr()` / `jsonAttr()` functions |
| `src/Internal/` | Internal array helpers |
| `tests/Feature/` | Pest tests |
| `.changeset/` | Pending changesets |

## Do not touch without explicit request

- No commits without explicit request
- GitHub workflows (`.github/`) and release config (`.changeset/config.json`)
- `CHANGELOG.md` (generated by Changesets)
- `composer.lock` / `pnpm-lock.yaml` and dependency versions
- do not edit TODO files
